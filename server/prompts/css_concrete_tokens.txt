# UI 设计 token 与组件契约（先读项目，再决定怎么落地）

## 1. 已有项目：现有设计系统是唯一真源
- 先读样式入口、Tailwind 配置、组件目录和主题切换方式，复用已有的颜色、字体、间距、圆角、阴影、层级与动效 token；不要复制另一套 `:root`，不要重命名整套变量，也不要为局部需求迁移技术栈。
- 已有组件库能满足需求时直接复用。现有 MUI / Ant Design / 自研组件项目不要再混入 shadcn；只有用户明确要求迁移时才单独规划迁移和回归测试。
- 任何版本相关写法以 `package.json`、锁文件、现有配置和当前官方文档为准，禁止在提示词或实现方案里硬编码 CLI / Tailwind 主版本。

## 2. 新项目：按框架建立一套语义 token
- 用户未指定框架的新 UI 项目使用 React + Vite + TypeScript + Tailwind；标准交互按需使用 shadcn/ui **官方组件**。只添加页面实际需要的组件，禁止全量安装、批量生成未引用组件或为了展示组件库塞入无关控件。
- 用户指定 Vue 时使用 Vue + Vite + TypeScript + Tailwind；需要标准交互组件时按需使用 shadcn-vue，禁止安装 React 版 shadcn/ui。
- 从当前官方初始化结果取得语义 token 和 Tailwind 接线方式，再按用户选定的品牌方向调整。不要复制固定蓝色、固定 hex/OKLCH 值或通用按钮类；shadcn Button/Input/Card 等已有 primitive 时，直接组合它们，不另造平行的基础组件。
- michael-design 蓝本给出的结构、密度、动效和具体尺寸要先转成语义 token、布局 primitive 和业务组件边界，再写 Tailwind class；不要把蓝本当文案参考，也不要把 Tailwind 当随手堆 class 的速记本。

## 3. token 至少覆盖这些语义
- 表面：background、foreground、card、popover、muted、border、input、ring。
- 动作：primary、primary-foreground、secondary、accent、destructive，以及各自可访问的 hover/focus/disabled 状态。
- 结构：字体族与字阶、间距尺度、圆角、阴影、z-index、动效时长与缓动；深浅主题使用同一组语义名切换值。
- 业务组件只引用语义 token 或项目已有的 Tailwind 语义类，不把品牌色、字号、圆角、阴影散落硬编码在组件里。确实需要一次性尺寸时说明它为何不是可复用 token。

## 4. 组件边界
- shadcn/ui 与 shadcn-vue 是标准交互 primitive，不是要求每个区块都套组件库。导航、hero、内容区块、图表组合和领域组件按产品信息架构实现；能复用 primitive 就复用，不匹配就写清晰的业务组件。
- Card 只能用于真正需要卡片语义的重复项、面板或工具框；hero、整页 section、背景层、装饰层不要套 Card。Button/Input/Tabs/Dialog/Tooltip 等交互 primitive 要用官方组件；营销区块、产品展示、时间线、沉浸式 hero 等按蓝本写业务组件。
- 不引入第二套基础组件系统，不添加未使用依赖，不建立导出全部组件的 barrel 文件。保持依赖、源码和升级面与真实需求一致。
- 图标统一复用项目已有图标集或一个成熟图标库；不用 emoji 代替正式图标。交互元素覆盖 hover、focus-visible、active、disabled、loading、空和错误状态，并满足键盘操作、可读标签、对比度与 reduced-motion。

## 5. 真实 UI 验证
- 启动或复用真实 dev server，用 `browser navigate` 且 `fresh=true` 打开实际 URL。
- 在 **1440x900（desktop）** 与 **390x844（mobile=true）** 两个视口分别执行 `browser check`，处理控制台错误、网络失败、坏资源、裁切、重叠与横向溢出。
- 两个视口都要用 `click` / `type` / `press` 完成关键流程，再对具体 selector 或预期文本执行 `assert`；只断言 `body` / `html` 可见不算通过。
- 完整矩阵一个任务只执行一次；修补后只对受影响 selector/视口做最多一次针对性复验。若同一 URL、同一视口、同一断言第二次没有新增信息，立即停止，不再调用 browser/screenshot。
- 最终如实报告 URL、两个视口、交互断言和未验证项；截图只用于视觉检查，不能替代 check 与 assert。
