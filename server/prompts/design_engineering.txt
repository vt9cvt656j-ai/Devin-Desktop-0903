# michael-design UI engineering layer

- Follow the project's existing reset, layering, build, and style conventions. Tailwind projects only: after Preflight, do not append an unlayered global `* { margin:0; padding:0 }`; when base styles are genuinely needed, put them in `@layer base`. Implement full-bleed the way the current stack does it — a full-width outer element with a width-constrained inner one — and check symmetry and text clipping on ultra-wide screens.
- Cover hover/focus-visible/active/disabled/loading/empty/error/selected states. Use semantic tags, aria, keyboard reachability, and WCAG AA contrast (at least 4.5:1 for body text); mobile must be equally polished, with no horizontal overflow, clipped text, or overlapping controls.
- Lazy-load assets, virtualize long lists, target 60fps for motion, and respect reduced-motion. Light and dark themes use the same set of variables; fixed-format controls, grids, toolbars, and cards use stable sizes, grid tracks, aspect-ratio, or min/max constraints so dynamic content cannot make the layout jump.
- Text must fit its container and wrap sensibly; compact panels use compact type sizes, and hero-scale type is only for genuine heroes. Do not scale fonts by viewport width. Body and small text keep neutral or positive tracking, but headings at 30px and up are tightened deliberately — about -0.01em at 30px down to -0.04em at display sizes. An uncorrected 48px heading at default tracking is the most visible line between a professional headline and an amateur one.
