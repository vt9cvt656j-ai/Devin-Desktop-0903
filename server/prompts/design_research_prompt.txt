第二步 规划完整 UI 架构：
- **页面 / 区块结构**：有哪几屏 / 哪些区块（导航 / 英雄区 / 能力区 / 案例 / 定价 / CTA / 页脚…），各自目的与要放的真实内容；
- **组件树**：拆成哪些可复用组件 + 层级；
- **设计 tokens（给具体值，能直接写进 CSS 变量）**：主色 / 辅助色 / 语义色（**含 hex**）、背景分层、字体族、字号阶、字重、间距尺度、圆角、阴影层级；
- **布局系统**：栅格 / Flex、容器最大宽、对齐与留白节奏；
- **响应式**：移动 / 平板 / 桌面断点与各自变化；
- **关键状态**：hover / focus / active / loading / 空 / 错误 / 禁用，要不要暗色；
- **动效**：哪些地方动、用什么（过渡 / keyframes / 滚动揭示 / 微交互）、时长缓动，尊重 prefers-reduced-motion；
- **技术取向（一律上现代框架，别糊裸 HTML）**：有现有栈就照它来；从零做**一律选一套现代前端框架**——**Vue3+Vite** 或 **React+Vite+TypeScript**（通用首选）/ Next.js·Nuxt（要 SSR/路由/全栈）/ SvelteKit，配 Tailwind + shadcn-vue·shadcn/ui 等组件库，**组件化 + 路由 + 状态管理**；**静态站 / 落地页 / 单页 / 简单 demo 也一律用脚手架（这正是用户要的——别自己替用户判定"这个简单，就裸 HTML 吧"）**。唯一例外：用户**明确点名**"纯 HTML 单文件 / 不要框架 / 一个 .html 搞定"时才用裸 HTML+CSS。蓝图里写清：选哪套栈、为什么、怎么 scaffold（如 `npm create vite@latest` / `npm create vue@latest`）、目录怎么分。
