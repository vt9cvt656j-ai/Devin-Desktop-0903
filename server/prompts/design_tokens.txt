# michael-design 数值层（字号阶 / 间距网格 / 圆角 / 阴影 / 时长）

这些是知识库里没有的具体数字，直接用。**颜色不在这里**——本轮配色来自
`knowledge_search(domain="michael-design")` 命中的蓝图，决策链见 design core。
项目已有 spacing / radius / shadow token 就沿用项目的，别另起一套。

## 配色：近黑白是默认；要上色，只能从知识库取

**默认就是近黑白 + 一个利落的主色 CTA。** 页面 ≥90% 面积是中性色（白/浅灰/近黑文字），
强调色只出现在主 CTA、链接、选中态、焦点环，以及每屏至多一处重点标记。section 底色只在
白与最浅中性之间交替，**绝不整段彩色底**。拿不准就少用色——近黑白配一个利落主色的页面，
永远比满页彩色高级。

要偏离近黑白，配色**必须来自知识库命中**，不许自己编，也不许照搬任何品牌的固定色：

```
knowledge_search(domain 传 michael-design, query 传 "<品类> palette")
```

取用顺序：① 本品类的站点蓝本命中了配色 → 成套采用；② 没有品类蓝本 → 用
enterprise-standard 的 **Curated Palette Library** 里最接近的一套，并说明取的是哪一条；
③ 已有项目 → 沿用项目自己的色板与 token 命名。**品类没列出来不是编色的许可。**

配色词汇表是「Tailwind 族+档」+「语义 token」两层：叙述与业务代码里禁止裸 hex，
蓝本给的 hex 要先贴到最近的 Tailwind 族+档（如 #17130d → stone-950）再用。

## 默认栈：React + Tailwind + shadcn/ui + 知识库配色，四样合起来用

空工作区/没有可沿用的栈时走默认分支。组件库是**装出来的，不是照着样子写的**：
`npx shadcn@latest init -b radix -p vega -y`（`-b`/`-p` 不能省，裸跑会弹交互菜单、
在非交互环境里等于什么都没装），再 `npx shadcn@latest add <本页真正用到的> -y`。
完整接线步骤在 scaffold 层。

**配色在这里合流**：init 会在 `src/index.css` 的 `:root` 生成
`--background / --foreground / --primary / --card / --muted / --border`。
把本轮从知识库命中的那套配色填进这些变量，业务组件只消费 `bg-background` /
`text-foreground` / `bg-primary` 这类语义类——不写裸 hex、不另造色板。

**禁止**自己写"shadcn 风格的" Button/Card/Input：手写控件缺 focus-visible、disabled、
键盘可达性和 Radix 浮层行为，一眼就差一截，这正是"自己写的组件很丑"的来源。
已有项目组合它自己的 primitive，同样不另造平行控件。
