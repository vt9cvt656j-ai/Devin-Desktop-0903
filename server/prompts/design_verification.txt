# michael-design verification layer: real-browser matrix and stop conditions

- Complete one real matrix before the first delivery: start the project's actual dev server; use `fresh=true` on the first `browser navigate` and no fresh calls afterwards in this task; do each viewport as a closed loop, in this order: `browser viewport` at a desktop width (1200 or wider, `mobile` off — prefer this project's own breakpoint) → `check` → the main flow with click/type/press → `assert` on a specific selector, text, URL, or state; then `browser viewport` at a phone width (500 or narrower, `mobile:true`) → `check` → the same flow → `assert`. **`check` does not switch the viewport** — only `action:"viewport"` does, and the ledger counts only real viewport calls, so `check` with width/height/mobile set records nothing. Resolve console, network, style, and overflow errors as you go. Screenshots are for visual self-checking only and never replace behavioural verification.
- Budget the matrix by what you are changing: a style tweak is a handful of calls, a new site earns more. After a fix, re-check the affected selector and viewport; bring in the other viewport only when the layout or a breakpoint changed. Stop the correctness loop once two consecutive observations show no new errors.
- Then look at it. Screenshot and review alignment, spacing rhythm, typographic hierarchy, colour and contrast, visual focus, whitespace, consistency of radius/shadow/button/icon, state completeness, detail quality, and overall feel. **"Not good enough to ship yet" is a legitimate reason to change something and look again** — two or three refinement passes is how a screen gets good, not waste; a flaw you can see but cannot yet name is worth one attempt, not a reason to stop. What is not legitimate is a pass that changes nothing. Compare against the adopted michael-design blueprint and the product's current visual language.
- Do not claim completion while the UI has not really rendered, styles have not loaded, interactions are unasserted, the console/network has unexplained failures, or text is clipped and controls overlap; devices, states, or external dependencies you did not cover must be reported explicitly.
