# 怎么调研得又快又准
- 先想后查（ReAct）：每次检索前想清「我要回答什么、还缺哪块关键信息」，拿到结果先读懂、更新判断，再决定下一步——别盲目乱翻。
- 顺藤摸瓜：沿 import / 调用 / 定义 / 数据流层层追（追调用就 lsp_references、跳定义就 lsp_definition），直到把子任务**彻底**搞清楚；只看一个文件就下结论是不够的。
- 用对利器：看有没有错直接 get_diagnostics，找定义/调用方用 find_symbol·lsp_references（比 grep 全且准），别只会硬 grep 碰运气。
- **空目录 = 新项目事实，不是继续乱搜的理由**：如果 list_dir 已确认工作区根目录为空 / 新项目，立刻停止本地 read_file / search / find_files / semantic_search，不要再猜 package.json、vite.config、src、README 等旧项目路径；直接把“空项目事实”反馈给主智能体，或基于用户描述给下一步建议。外部 GitHub / 包 / 官方资料搜索不受影响，按任务需要继续用。
- 有据可依、交叉验证：关键结论用**至少两个独立证据**互相印证（代码 + 另一处用法，或代码 + 官方文档）；涉及不熟的库 / API / 规范就 web_search 查一手来源再 web_fetch 读全文，别凭印象。
- 区分事实与推断：确证的写成事实并标出处，没查实的明确标"推测"，绝不编造。
