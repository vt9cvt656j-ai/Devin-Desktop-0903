# 做「产品 UI / 官网 / 界面」——先判断该走多重，别一条道疯跑、别对着截图反复磨

用户让你**设计 / 做界面 / 页面 / 产品 UI / 官网**时看这份。**最高原则：先想清楚要做成什么样、一次搭对，别一边写一边疯狂截图试错。** 三件让用户参与的工具（design_board 衣橱 / preview_choices 功能柜 / visual_compare 对比）**用不用、什么时候用，你自己判断——绝不是每次都机械摆一遍。**

## ⓪ 先判断力度（最重要，别一刀切）
- **从零做完整产品界面 / 官网 / 应用 / 落地页 / 整体重设计** → 走下面完整流程。
- **往已有项目加一块 / 改个样式 / 做单个组件 / 用户只是问"这块该怎么设计、怎么布局"** → **别摆衣橱、别新起脚手架**：读一下项目现有栈和设计 token，跟着做那一小块；用户只是问就正面给建议 + 必要时做出来看。
- **已有项目一律跟随它的技术栈**（先读 package.json）；是"整套"还是"小改"拿不准，一句话问用户，别默认套最重的流程。

## 从零做整套：想清楚 → 一次搭对 → 起服务扫一眼（这套按需走，不是每步都硬做）
1. **先读懂真实产品**：list_dir + read 真实源码 / 文案 / 配置，**说得出这个产品 3 条具体、别处不通用的事实**（真功能名 / 真卖点 / 真品牌调性）。说不出、只会说"一个 AI IDE / 类似 Cursor" = 没读够，回去读。别脑补、别套通用模板，抓住产品**自己的**视觉调性。
2. **定视觉方向（衣橱按需，自己判断要不要用）**：
   - **从零定整站视觉、且该让用户拍板** → 用**衣橱**：为 2-3 个明显不同的方向各写一段精炼英文 generate_image prompt（2-4 句：主体+版式 / 风格气质 / 关键细节 = 真文案 + 2-3 个 hex 主色 + 字体感；别塞 "mockup/Dribbble" 这种 AI 味词）→ generate_image ×3 存 .wardrobe/ → design_board 让用户点选。**整个项目衣橱只在这儿用一次定调性，不是每个界面都摆。**
   - **已有明确品牌 / 风格、或用户已经说了要什么样** → 直接定一套 token 开干，**别硬摆衣橱**。
   - **想做到一流、不落 AI 味 → 先看真参考再动手**（这是拉开和模板垃圾的关键）：搜 2-3 个设计参考（codrops_search / awwwards_search / dribbble_search / css_tricks_search）+ browser `design` 抓 1-2 个对标站的真实设计系统（配色 / 字体 / 间距 / 圆角 / 动效）。定主色板可 `color_search` 找专业配色，图标一律 `iconify_search` 找真 SVG（别用 emoji）。别凭空拍脑袋堆样式。
3. **落一套设计 token 当单一真源**：CSS 变量 / Tailwind theme（主色+浅深变体、背景 / 表面、文字 / 次要、字体族、字阶、间距、圆角、阴影），之后每个组件**一律引用 token**、绝不把颜色 / 字号硬编码散落。**字体别默认 Inter**，选有对比的搭配。
4. **用 Vite + Vue/React + Tailwind 组件化写真实项目**（即使静态站 / 落地页也用框架，别丢一个裸 index.html 当交付）；已有框架就用它。每个区块 = 独立组件（`<Nav/>` `<Hero/>`…），别糊成巨型文件。**大文件先 write 一个能跑的骨架、再 edit 每次补 ≤50 行**——一次 write 塞几百行会被截断成半个文件、一跑就崩。图标用 lucide / heroicons，配图用**真图**（源码里现成的 / Unsplash / 自己跑起来 screenshot），**别 emoji / 灰占位框 / 自造粗糙 SVG**。组件多且互不依赖、且量真的大，才 run_worker 并行写；否则自己一个个写。
5. **验证 = 起服务真跑一遍、扫一眼确认，别疯狂截图**：run_cmd 起 dev server → browser 打开，**点一遍关键交互确认是真接通的、不是空壳**（导航 / 按钮 / 表单 / 登录）→ 觉得哪儿不对，再 inspect / network 查**那一处**。**绝不每改一点就截一张图、绝不对着截图来回磨**——一次搭到位、扫一眼确认能跑 + 对得上，可以减少无效往返。要和设计图比就 visual_compare **看一次差距、改完再看一次**就够，别循环刷截图。窄屏扫一眼即可。
6. **反 AI 味**：多区块有密度层次（特性网格 / 数据指标 / logo 墙 / 对比表 / FAQ / footer）、非对称有节奏的版式、每个组件精心 style（按钮 / 卡片有底色圆角阴影 + hover 态）；配色语义化，别烂大街的紫→蓝渐变；文案写这个产品**具体的**卖点 / 场景，别"赋能 / 一站式 / 高效"这种空话。

一句话：**判断力度 → 读懂真产品 → 想清楚一次搭对（框架组件化、大文件分块写）→ 起服务点一遍确认能跑，别疯狂截图试错。** 衣橱 / 功能柜 / visual_compare 你自己判断按需用，不是每次都机械摆一遍。
